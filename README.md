# 🤖 وكيل خدمة العملاء الذكي (Customer Service AI Agent)

مشروع تعليمي كامل وقابل للتشغيل فعليًا، يوضح كيف يُبنى **وكيل ذكاء
اصطناعي حقيقي (AI Agent)** باستخدام Python وFastAPI وLangGraph،
بحيث لا يكتفي بالرد على العميل كمحادثة عادية، بل **يحلل الرسالة،
يتخذ قرارًا، ثم ينفذ إجراءً فعليًا** عبر أدوات (Tools) حقيقية تتعامل
مع قاعدة بيانات SQLite.

> ⚠️ **تنبيه مهم:** جميع البيانات في هذا المشروع (قاعدة المعرفة،
> التذاكر، العملاء) هي بيانات **تجريبية لأغراض تعليمية فقط**، ولا
> يقوم المشروع بإرسال أي بريد إلكتروني أو رسالة حقيقية؛ عمليات
> التصعيد والإشعارات هنا **محاكاة فقط** داخل قاعدة البيانات.

---

## 1. وصف المشروع

الوكيل الذكي يستقبل رسالة العميل عبر واجهة `/chat`، ثم يمرّ بالتسلسل
التالي (مبني كرسم بياني LangGraph حقيقي):

```
رسالة العميل
   ↓
تنظيف وفهم الرسالة
   ↓
تحديد اللغة (عربي/إنجليزي)
   ↓
البحث في قاعدة المعرفة (RAG بسيط)
   ↓
تحليل نوع المشكلة واتخاذ القرار
   ↓
اختيار الأداة المناسبة (Tool)
   ↓
تنفيذ الأداة فعليًا (قاعدة بيانات SQLite)
   ↓
حفظ المحادثة
   ↓
إعادة الرد النهائي للعميل
```

القرار النهائي يكون دائمًا واحدًا من أربعة خيارات:

| القرار (action) | متى يُستخدم؟ |
|---|---|
| `answer` | توجد إجابة موثوقة في قاعدة المعرفة |
| `create_ticket` | لا توجد إجابة موثوقة، والمشكلة تحتاج متابعة موظف |
| `escalate` | الرسالة تحتوي مؤشرات حساسة (اختراق، احتيال، غضب شديد...) |
| `check_ticket` | العميل يسأل عن حالة تذكرة موجودة برقمها |

## 2. الفرق بين Chatbot عادي وAI Agent حقيقي

| Chatbot عادي | AI Agent (هذا المشروع) |
|---|---|
| يرد بنص فقط | يتخذ **قرارًا** بين عدة خيارات ممكنة |
| لا ينفذ أي إجراء حقيقي | ينفذ إجراء فعليًا: يفتح تذكرة، يصعّد حالة، يحدّث قاعدة بيانات |
| لا "يتذكر" ما حدث فعليًا | يحفظ كل محادثة وتذكرة في قاعدة بيانات حقيقية |
| غالبًا "يخترع" إجابات | يعتمد فقط على قاعدة معرفة محددة (RAG)، وإن لم يجد إجابة موثوقة يفتح تذكرة بدل التخمين |
| يتوقف إن تعطّل مزود الذكاء الاصطناعي | يعمل بوضعين: Rule-Based (بدون OpenAI) وOpenAI Mode، مع رجوع تلقائي آمن |

## 3. بنية المشروع

```text
customer_service_agent/
│
├── app/
│   ├── __init__.py
│   ├── main.py        # تطبيق FastAPI ونقاط النهاية (Endpoints)
│   ├── agent.py        # رسم LangGraph الكامل ومنطق اتخاذ القرار
│   ├── tools.py        # الأدوات الفعلية التي ينفذها الوكيل
│   ├── models.py        # نماذج Pydantic (Request/Response)
│   ├── database.py    # إعداد SQLAlchemy وجداول قاعدة البيانات
│   ├── rag.py          # نظام RAG بسيط للبحث في قاعدة المعرفة
│   ├── prompts.py      # System Prompt الخاص بوضع OpenAI
│   └── config.py        # قراءة إعدادات المشروع من .env
│
├── data/
│   └── knowledge_base.txt   # قاعدة المعرفة النصية (عربي/إنجليزي)
│
├── frontend/
│   └── index.html      # واجهة بسيطة (HTML/CSS/JS) باتجاه RTL
│
├── tests/
│   └── test_agent.py    # اختبارات آلية شاملة (pytest)
│
├── requirements.txt
├── .env.example
├── .gitignore
├── README.md
└── smoke_test.py         # سكربت تجريبي سريع لتجربة كل السيناريوهات
```

### شرح كل ملف

- **`app/config.py`**: يقرأ الإعدادات (مفتاح OpenAI، رابط قاعدة
  البيانات، حد الثقة الأدنى لـ RAG...) من ملف `.env` باستخدام
  `pydantic-settings`.
- **`app/database.py`**: يعرّف محرك SQLAlchemy وجداول
  `customers`, `tickets`, `conversations`، ودالة `init_db()` التي
  تُنشئ الجداول تلقائيًا عند أول تشغيل.
- **`app/models.py`**: نماذج Pydantic للتحقق من صحة المدخلات
  والمخرجات (`ChatRequest`, `ChatResponse`, `TicketCreate`, ...).
- **`app/rag.py`**: يقسّم `knowledge_base.txt` إلى أقسام، ويبحث عن
  أقرب قسم لسؤال العميل باستخدام تشابه جيب التمام (Cosine
  Similarity) المحسوب يدويًا، دون أي مكتبة ذكاء اصطناعي خارجية.
- **`app/prompts.py`**: يحتوي الـ System Prompt المستخدم فقط عند
  تفعيل وضع OpenAI.
- **`app/tools.py`**: الأدوات السبع التي يستخدمها الوكيل
  (`search_knowledge_tool`, `create_ticket_tool`,
  `get_ticket_status_tool`, `update_ticket_status_tool`,
  `escalate_ticket_tool`, `save_conversation_tool`,
  `get_customer_history_tool`)، وكل أداة موثقة بتعليقات عربية.
- **`app/agent.py`**: يبني رسم LangGraph (`StateGraph`) الذي يربط كل
  الخطوات السابقة معًا، ويحتوي منطق اتخاذ القرار (Rule-Based
  و OpenAI مع رجوع تلقائي آمن).
- **`app/main.py`**: تطبيق FastAPI ونقاط النهاية (Endpoints) الكاملة.
- **`frontend/index.html`**: واجهة تجريبية بسيطة بالعربية واتجاه RTL
  للتحدث مع الوكيل مباشرة من المتصفح.
- **`tests/test_agent.py`**: اختبارات pytest تغطي كل السيناريوهات
  المطلوبة.
- **`smoke_test.py`**: سكربت يشغّل عدة أمثلة فعلية ويطبع نتائجها
  بالتفصيل، مفيد للتأكد السريع أن كل شيء يعمل.

## 4. خطوات التشغيل في Visual Studio Code (Windows)

### 4.1 فتح المشروع
افتح مجلد `customer_service_agent` في Visual Studio Code
(File → Open Folder...).

### 4.2 إنشاء البيئة الافتراضية (Virtual Environment)

افتح الطرفية (Terminal) داخل VS Code (من القائمة Terminal → New
Terminal)، ثم نفّذ:

```powershell
python -m venv .venv
```

### 4.3 تفعيل البيئة الافتراضية

```powershell
.venv\Scripts\Activate.ps1
```

> إذا ظهرت رسالة خطأ متعلقة بسياسة التنفيذ (Execution Policy)، نفّذ
> الأمر التالي مرة واحدة كمسؤول (Administrator) ثم أعد المحاولة:
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```

### 4.4 تثبيت المكتبات المطلوبة

```powershell
pip install -r requirements.txt
```

### 4.5 إنشاء ملف `.env`

انسخ ملف `.env.example` وأعد تسميته إلى `.env` (نفس المجلد الرئيسي):

```powershell
copy .env.example .env
```

القيم الافتراضية تجعل المشروع يعمل فورًا **بدون أي مفتاح OpenAI**
(`USE_OPENAI=false`)، وهذا كافٍ لتجربة كل السيناريوهات.

### 4.6 تشغيل المشروع

```powershell
uvicorn app.main:app --reload
```

سيظهر في الطرفية أن الخادم يعمل على:
`http://127.0.0.1:8000`

### 4.7 فتح توثيق Swagger التفاعلي

افتح المتصفح على الرابط التالي لتجربة كل نقاط النهاية مباشرة:

```text
http://127.0.0.1:8000/docs
```

## 5. أمثلة جاهزة لتجربة كل Endpoint

يمكن تجربة الأمثلة التالية مباشرة من صفحة Swagger (`/docs`)، أو عبر
أي أداة مثل Postman أو curl.

### مثال 1: سؤال له إجابة في قاعدة المعرفة (action = answer)

`POST /chat`

```json
{
  "customer_id": "CUST-1001",
  "message": "لم تصلني رسالة إعادة تعيين كلمة المرور"
}
```

الرد المتوقع (مختصر):

```json
{
  "action": "answer",
  "reply": "لإعادة تعيين كلمة المرور، اذهب إلى صفحة تسجيل الدخول...",
  "source": "knowledge_base.txt#إعادة تعيين كلمة المرور | Password Reset",
  "ticket_id": null,
  "confidence": 0.32
}
```

### مثال 2: سؤال غير موجود في قاعدة المعرفة (action = create_ticket)

```json
{
  "customer_id": "CUST-1002",
  "message": "أريد إضافة ميزة الدفع بالتقسيط داخل التطبيق"
}
```

الرد سيكون بـ `"action": "create_ticket"` مع `ticket_id` جديد.

### مثال 3: حالة حساسة تستدعي التصعيد (action = escalate)

```json
{
  "customer_id": "CUST-1003",
  "message": "حسابي تم اختراقه ويوجد خصم مالي غير معروف، أريد التحدث مع مدير الآن"
}
```

الرد سيكون بـ `"action": "escalate"` مع `"priority": "urgent"`.

### مثال 4: متابعة حالة تذكرة موجودة (action = check_ticket)

بعد إنشاء تذكرة (مثال 2 أعلاه) واستلام رقمها (لنفترض 1)، أرسل:

```json
{
  "customer_id": "CUST-1002",
  "message": "ما هي حالة التذكرة TCK-1؟"
}
```

### مثال 5: إنشاء تذكرة يدويًا بدون المرور عبر الوكيل

`POST /tickets`

```json
{
  "customer_id": "CUST-1004",
  "subject": "استفسار عن فاتورة",
  "description": "أحتاج نسخة من فاتورة الشهر الماضي",
  "category": "billing",
  "priority": "low"
}
```

### مثال 6: تحديث حالة تذكرة

`PATCH /tickets/1/status`

```json
{ "status": "resolved" }
```

### مثال 7: عرض سجل محادثات عميل

`GET /customers/CUST-1001/history`

## 6. شرح قاعدة البيانات (SQLite)

يستخدم المشروع SQLite افتراضيًا (ملف `customer_service.db` يُنشأ
تلقائيًا في المجلد الرئيسي عند أول تشغيل). الجداول الثلاثة:

- **`customers`**: بيانات العميل الأساسية، تُنشأ تلقائيًا أول مرة
  يتواصل فيها عميل جديد.
- **`tickets`**: كل تذكرة دعم تحتوي حالة (`open/in_progress/
  resolved/closed`) وأولوية (`low/medium/high/urgent`) وحقل
  `escalated` يوضح إن كانت مصعّدة.
- **`conversations`**: سجل كل رسالة بين العميل والوكيل، مع الإجراء
  المتخذ (`action`) ومصدر القرار (`rule_based` أو `openai`).

لا حاجة لتثبيت أي خادم قاعدة بيانات منفصل؛ SQLite يعمل كملف واحد
فقط، وهذا يجعل تشغيل المشروع بسيطًا جدًا للطلاب.

## 7. شرح نظام RAG المستخدم

نظام الاسترجاع المعزز بالبيانات (RAG) هنا **بسيط جدًا ومقصود أن يكون
كذلك** تعليميًا:

1. يقرأ ملف `data/knowledge_base.txt` ويقسّمه إلى أقسام (كل قسم
   يبدأ بعنوان `## `).
2. يحوّل سؤال العميل ومحتوى كل قسم إلى "كلمات" (Tokens).
3. يحسب **تشابه جيب التمام (Cosine Similarity)** بين متجه تكرار
   كلمات السؤال ومتجه تكرار كلمات كل قسم - يدويًا وبدون أي مكتبة
   Embeddings خارجية.
4. يختار القسم الأعلى تشابهًا، ويقارن درجته بـ `MIN_RAG_SCORE`
   (0.20 افتراضيًا) في ملف `.env`.
5. إن كانت الدرجة أقل من الحد الأدنى، يُعتبر أنه **لا توجد إجابة
   موثوقة**، ولا يُسمح للوكيل باستخدامها؛ ينتقل القرار عندها إلى
   `create_ticket` بدلًا من "اختراع" إجابة غير مؤكدة.

يمكن لاحقًا استبدال هذا البحث النصي البسيط بـ FAISS أو Chroma مع
Embeddings حقيقية من OpenAI، دون تغيير أي كود خارج `app/rag.py`.

## 8. شرح استدعاء الأدوات (Tool Calling)

الوكيل **لا يكتفي بالرد النصي أبدًا**؛ في كل مرة يتخذ قرارًا، فإنه
يستدعي أداة (Tool) حقيقية من `app/tools.py` تنفذ إجراءً فعليًا على
قاعدة البيانات:

| القرار | الأداة المستدعاة |
|---|---|
| `answer` | `search_knowledge_tool` (تم استدعاؤها مسبقًا أثناء البحث) |
| `create_ticket` | `create_ticket_tool` |
| `escalate` | `escalate_ticket_tool` |
| `check_ticket` | `get_ticket_status_tool` |
| (دائمًا في النهاية) | `save_conversation_tool` لحفظ سجل المحادثة |

كل أداة تعيد `dict` منظمًا يحتوي `success` وبيانات العملية، مما
يسهّل على أي مطوّر لاحقًا تحويلها إلى Function Calling حقيقي في
OpenAI أو أي إطار عمل آخر للوكلاء.

## 9. شرح System Prompt (وضع OpenAI)

عند ضبط `USE_OPENAI=true` ووضع مفتاح صالح في `OPENAI_API_KEY`، يتم
إرسال System Prompt احترافي (موجود بالكامل في `app/prompts.py`)
يُلزم النموذج بالقواعد التالية:

- عدم اختراع سياسات أو معلومات غير موجودة في قاعدة المعرفة.
- عدم طلب كلمة المرور أو رمز التحقق أو رقم البطاقة البنكية أبدًا.
- دعم اللغتين العربية والإنجليزية.
- تصعيد الحالات الحساسة فورًا (اختراق، احتيال، غضب شديد...).
- إعادة القرار **بصيغة JSON منظمة فقط** مطابقة لنموذج
  `AgentDecision`، وليس كنص حر.

وإذا فشل الاتصال بـ OpenAI أو كان الرد غير صالح كـ JSON، يرجع النظام
تلقائيًا وبأمان إلى **وضع القواعد (Rule-Based Mode)** بدل توقف
الخدمة بالكامل.

التصعيد، متابعة تذكرة موجودة، متابعة تذكرة غير موجودة، والعمل

```powershell
python smoke_test.py
```

يطبع هذا السكربت تفاصيل كل سيناريو: رسالة العميل، القرار، الأداة
المستخدمة، الرد، المصدر، ورقم التذكرة.

## 11. الواجهة الأمامية البسيطة (Frontend)

بعد تشغيل الخادم (`uvicorn app.main:app --reload`)، افتح ملف
`frontend/index.html` مباشرة في المتصفح (Double-click عليه، أو
Live Server من VS Code). الواجهة:

- مصممة بالكامل باللغة العربية واتجاه RTL.
- تحتوي حقلًا لمعرّف العميل وآخر لكتابة الرسالة.
- تعرض القرار المتخذ (بلون مختلف لكل نوع)، والرد، والتصنيف،
  والأولوية، ورقم التذكرة، ومصدر الإجابة.
- تعرض حالة تحميل أثناء انتظار الرد، ورسالة خطأ واضحة إذا تعذّر
  الاتصال بالخادم.

## 12. أفكار لتطوير المشروع لاحقًا

- استبدال RAG البسيط بـ FAISS أو Chroma مع Embeddings حقيقية.
- إضافة LangGraph Streaming لعرض كل خطوة من خطوات تفكير الوكيل
  فور حدوثها في الواجهة الأمامية.
- ربط `escalate_ticket_tool` بإشعار حقيقي (Slack/Email/WhatsApp).
- إضافة نظام مصادقة (Authentication) للعملاء والموظفين.
- إضافة لوحة تحكم (Dashboard) لعرض إحصاءات التذاكر والمحادثات.
- دعم إرفاق الملفات والصور ضمن رسائل العميل.
- تحويل الأدوات في `tools.py` إلى OpenAI Function Calling رسمي.
